# 工业设备状态记录终端

STM32F103CBT6 + FreeRTOS + FatFs 的数据记录板。板上接 MPU6050、BMP280、DS18B20、DHT22、HC-SR04、
光敏电阻和电池分压，10 Hz 采一轮，拼成一行 CSV 写进 SD 卡。

设计目标是：掉电最多丢最后一批、已经 `f_sync` 过的数据不会写坏、卡拔下来能直接当 CSV 打开。
做到了多少见第 5 节，没做到的在第 10 节。

板上现在跑 APP ver 76（镜像版本 7），带 Bootloader，升级走串口，不需要 ST-Link。

## 1. 硬件

| 模块 | 接口 | 引脚 | 备注 |
|---|---|---|---|
| MCU | STM32F103CBT6 | — | 72 MHz，20 KB RAM，128 KB Flash（Boot 16 KB + App 108 KB + 参数区 4 KB）|
| 调试串口 | USART1 | PA9(TX) / PA10(RX) | 115200-8-N-1；对时、升级、命令都走这条 |
| OLED 0.96" | 软件 I2C | PB10(SCL) / PB7(SDA) | 2026-10-20 从 PB8/PB9 换过来 |
| MPU6050 | 软件 I2C | PA2(SCL) / PA3(SDA) | 三轴加速度 + 角速度 + 片内温度 |
| BMP280 | 软件 I2C（和 MPU6050 共用）| PA2 / PA3 | 气压，×10 Pa；地址 0x76 或 0x77 |
| DS18B20 | 单总线 | PB14 | 要 4.7 kΩ 上拉 |
| DHT22 | 单总线（开漏）| PB15 | 模块自带 10 kΩ 上拉 |
| HC-SR04 | TRIG 输出 / ECHO 输入捕获 | PB5 / PB6 | ECHO 必须接 TIM4_CH1 |
| W25Q64 | 软件 SPI | PA8(SCK) / PA11(MISO) / PA12(MOSI) / PB13(CS) | 8 MB，放固件金副本和掉卡缓存 |
| SD 卡模块 | SPI1 + 软件 CS | PA4(CS) / PA5(SCK) / PA6(MISO) / PA7(MOSI) | 模块要供 5 V；卡 ≤32 GB 且 FAT32 |
| ADC | ADC1 + DMA（循环）| PA1(光照) / PB0(电池分压 1/3) | 后台自动刷 `AD_Value[]` |
| 蜂鸣器 | GPIO | PB12 | 低电平响 |
| 电源键 | GPIO 输入 | PA0 | 短按翻页（数据 / 存储 / 运行），长按安全关机 |
| 调试器 | ST-Link | SWD | 只有烧固件用，串口升级不需要 |

引脚这块踩过三回，记一下：

- I2C 本来打算放 PB6/PB7，OLED 模块装上去正好盖住那两个针脚，杜邦线插不进去，改到 PB10/PB7
- 换过去那版又不亮，是插座上 VCC 和 GND 装反了，按 `OLED.c` 头注释里的线序改的线
- PC14/PC15 是 LSE 晶振脚，一动 RTC 就停摆，所以能用的 IO 比数据手册上数出来的少

## 2. 软件结构

```
task_ACQ (6) ──Record_t 44B──▶ [队列 深度 8] ──▶ task_PROC (2)
 100ms 硬节拍                                     │ 出队 → 拼 CSV 行
 绝不阻塞                                         │ 填 512B 乒乓缓冲（传指针，零拷贝）
                                                  ▼
                                        [缓冲指针队列] ──▶ task_SD (1) ──▶ FatFs ──▶ SD
task_KEY (2)    20ms  ──▶ 翻页 / 统计 / 长按关机
task_DISP (1)  200ms  ──▶ OLED（唯一所有者）
task_sensor (1)   1s  ──▶ DS18B20 + BMP280 + DHT22 + 超声波
task_GOLDEN (1) 一次性 ──▶ 把当前固件备份进 W25Q64
```

| 任务 | 优先级 | 栈（字）| 周期 | 干什么 |
|---|---:|---:|---|---|
| ACQ | 6 | 128 | 100 ms | 采样并组装记录，`xQueueSend` 超时 0，漏拍要记账 |
| PROC | 2 | 320 | 队列驱动 | 拼 CSV、填乒乓缓冲，高频串口打印基本都在这里 |
| KEY | 2 | 64 | 20 ms | 消抖状态机，栈不够，禁止 printf |
| DISP | 1 | 224 | 200 ms | OLED 唯一所有者，心跳 + SD 错误码 + 30 s 无操作黑屏 |
| sensor | 1 | 320 | 1 s | 单总线温度、气压、湿度、超声波 |
| SD | 1 | 448 | 队列驱动 | 全工程唯一允许调 `f_xxx` 的地方 |
| GOLDEN | 1 | 192 | 一次性 | 后台把内部 Flash 拷进 W25Q64 |

定下来之后没再动过的几条：

1. **SD 的慢压在最低优先级**。采集链不等 SD：一批攒 512 B（大约 6 行文本、600 ms 的量），
   而 `f_write` 平均 10 ms、最长 124.5 ms。注意这是"不等它"，不是"永不阻塞"——
   I2C 那几个互斥量还是 `portMAX_DELAY`。
2. **FatFs 只出现在 `task_sd.c` 里**（`_FS_REENTRANT=0`）。从结构上不让两边同时碰文件系统，
   比加锁省事，也不用担心优先级反转。
3. **所有任务的内存静态分配**，都是 `.bss` 里的具名数组，堆只剩 64 B 名义值，
   对着 `map` 文件能逐项对账。

## 3. 存储

文件名：

```
YYMMDDNN.CSV    数据，NN 是当天第几个（从 01 起）
YYMMDD90.CSV    事件，行首带 #，PC 侧解析器跳过
```

按本地日期切文件（`MyRTC_GetLocalDateTime`），本地 00:00 换新的。一天满量大约 864,000 行、80 MB。

CSV 是 17 列，`crc` 是前面 16 列文本算出来的 CRC-16/KERMIT，覆盖到最后一个逗号之前：

```csv
seq,tick,press,rtc,ax,ay,az,gx,gy,gz,temp_ds,temp_chip,humi,light,vbat,sonar_mm,crc
1,100,1021230,1793697276,-213,-1115,1669,1,-1,-1,-32768,2303,65535,2278,2088,52,2675
```

几个要留意的列：

| 列 | 说明 | 无效值 |
|---|---|---|
| `rtc` | 真 Unix 秒（UTC），不带时区 | 0 表示 RTC 没走，见第 4 节 |
| `temp_ds` | DS18B20，×100 ℃ | `-32768`：转换没完成 |
| `humi` | DHT22，×10 %RH | `65535`：没读到 |
| `light` / `vbat` | ADC 原始值 0~4095 | — |
| `sonar_mm` | 超声距离 mm | 0：没回波 |

为了扛住掉电和坏卡做的几件事：

| 机制 | 做法 |
|---|---|
| 写放大 | 512 B 攒够再写，正好一个扇区 |
| 落盘节奏 | 每批 `f_sync`，所以承诺只丢最近一批；EXP-03 里 8 次掉电各丢 2~6 行 |
| 缓冲所有权 | 乒乓双缓冲、队列传指针，拿了必须交回去，不交就停摆 |
| 掉卡缓存 | 卡不在时进 W25Q64，故障期间降到 1 条/秒，卡回来自动重放（`# SD_REPLAY`）|
| 写失败 | 真 `FR_*` 错误立刻卸载卷、每 3 s 重试；只有短写走三连击 |
| 安全关机 | 长按 → 停采集 → 写完队列 → `f_close` → 屏上 `SAFE TO OFF` |
| 金副本 | 升级前把当前固件存进 W25Q64，Boot 可以直接回退 |
| 卡满 | <200 MB 告警，<80 MB 删最旧（至少留最近 3 天，每次挂载最多删 3 个）|
| 丢数据记账 | 6 种丢失原因各一个计数器，冲进事件文件 `# LOST,<rtc>,<n>,<reason>` |

最后一条是原则问题：丢可以，不能悄悄丢。

## 4. 时间

规则写在 `MyRTC.h` 里：

1. CSV 的 `rtc` 列永远是 UTC，不带时区，这样换机器、跨时区拷数据都不会有歧义
2. 给人看的时间（文件名、屏显）加 8 小时，走 `MyRTC_GetLocalDateTime()`
3. 「配过」和「对过」是两件事——`BKP_DR1` 表示初始化过，`BKP_DR5` 才表示有人对过时

板上装了 CR2032，断电 RTC 继续走，开机打 `BKP magic hit -> keep counter` 就说明备份域没丢。
只有换电池、备份域被复位、LSE 起不来这几种情况，才会拿编译时刻当初始值。
在跑但时间不对的时候，串口发 `T<unix>` 或者跑 `time_sync.py` 对时。

### 掉电与掉卡（2026-11-09）

之前测掉电是拿复位模拟的，心里没底，这天改成真拔电源，一共 25 次：

卡插回去回写是 2.0 批/秒，1,492 批用了 12.4 分钟。以前文档里写的 63 分钟和 12 小时都是错的，
前者漏了降采样，后者没算每批条数。

顺便修掉一个能让整机静默的死循环：`SD_Init()` 里重试计数用的是 `uint8_t`，上限却写 `SD_IDLE_RETRY`
= 300，`i < 300` 恒真，CMD0 那段永远退不出来——没插卡就是黑屏、一个字节都不打，只能复位。
变量改 `uint16_t` 之后正常打出 `CMD0 NO RESPONSE (r1=0x00) after 300 tries`。
同一天还把无卡时的重试退避改了：以前每 0.65 s 重跑一遍完整初始化加十行日志，`drop` 冲到 235；
改成首次 300 轮带全量诊断、之后 24 轮（约 50 ms）只管关键行、间隔 3.2 s，`drop` 降到 2。

顺带说一句，这次排查里我自己被 ST-Link 骗过一次：`ST-LINK_CLI -c SWD` 会复位并 halt 住内核，

## 6. 卡拔下来之后怎么查

`sd_analyze.py` 扫一遍 `YYMMDDNN.CSV`，给的是"这批数据能不能用"，不只是数行数：

逐小时均值，`recorder_gui.pyw` 里还有曲线。判据和输出见 [离线分析工具](docs/离线分析工具.md)。

## 7. 串口升级

PC 侧 `flash_app.py`（或者双击 `升级固件.bat`，也可以在 GUI 里点"固件升级向导"）：

```text
python flash_app.py              # 探针 → 请求复位 → 传 → 校验 → 跳转
python flash_app.py --check      # 只算体积和 CRC，不连串口
python flash_app.py --stage data # 只发数据不发 X，用来单独验证写 Flash 那段
```

协议是文本行，`\r\n` 结尾：

```text
PC → MCU : E<字节数>   D<块号><hex>   X<整体CRC16>   U（请求进 Boot）
MCU → PC : E0/E1   K<块号>   N<块号>   PASS   FAIL <原因>   WAIT
```

停等，每块 128 字节，等到 `K` 才发下一块——擦写 Flash 那段要关中断，串口这时候的字节会丢。

升级模式里空闲 30 秒会自己退回 App（`UP_IDLE_CANCEL_WAITS`），所以中间别停太久，被取消了再发一次 `U`。

11-07 起是**先落盘再切**：整包先写进 W25Q64 暂存区（`0x7E1000`，108 KB），每页写完立刻回读比对，
`X` 校验过了才动内部 Flash。所以传输期间断电不影响旧固件；搬到一半断了，下次开机自己装回去。
自愈两条兜底：暂存区装不回来就回金副本，再不行才停在升级模式等人。

## 8. 编译

Keil MDK5 + ARMCC V5.06u7（AC5），`-O1`，别开 `-O3`。App 工程是 `Project.uvprojx`，
Boot 在 `Boot\Project.uvprojx`。Keil 关着的时候可以命令行编：

```powershell
UV4.exe -b Project.uvprojx -j0 -o build.log            # 增量
UV4.exe -r Boot\Project.uvprojx -j0 -o build_boot.log  # 全量
```

`MyRTC.c` 拿 `__DATE__` / `__TIME__` 给 RTC 设初值，所以同一份源码不同时刻编出来的 bin CRC 不一样，
这不是代码变了。SD 卡要先在 PC 上格式化成 FAT32，工程里把 `f_mkfs` 裁掉了。

## 10. 没做的

| 项 | 状态 |
|---|---|
| Tickless idle | 没开：内核时基和 HAL 冲突，而且实测耗电大头是屏幕和 LDO，收益不大 |
| STOP 模式 | 候选，要真做电池供电再说 |
| P-MOS 断电重挂 SD | 没做，PB10 被 OLED 占了之后打算挪到 PA15 |
| 金副本单槽的掉电安全 | 没做，保存窗口不是掉电安全的，下一版要做双槽或提交头 |
| PVD 掉电检测 | 没做，现在只有每批 `f_sync` + IWDG + 关机握手 |

还有一堆边界条件不好在表格里写，都在 [docs/limitations.md](docs/limitations.md)：
只在一张卡上验过、25 次掉电只够排除失败率高于 15% 的情况、7.0 小时是从 80 分钟外推的、
10-29 那个 tick 台阶没定案。主张和证据的对照在 [docs/evidence-matrix.md](docs/evidence-matrix.md)。

卡上还留着几个开发期的历史产物：`70010101.CSV`（8.7 MB，LSE 没起振时 RTC 恒 0，
文件名退化成 1970，现在会在屏上报警），以及 `26101802 / 26101901 / 26101903` 三个尾巴带二进制垃圾的文件。
