# 工业设备状态记录终端（STM32F103CBT6 + FreeRTOS + FatFs）

多通道数据采集终端：姿态、温度、湿度、气压、光照、电池电压、超声波距离，10 Hz 同步采集，
写入 SD 卡 CSV。采集链按设计把 SD 慢隔离在最低优先级；目标是**掉电最多丢一批，已 sync 的数据不丢、文件可读**。

> **当前状态：v1.1 可用（APP ver 75 / 镜像版本 6），17 天实机数据已按第三版口径重算**（2026-10-18 ~ 11-03）
>
> 2026-11-09 这一天补了三块短板：**真断电 25 次**（安装期 20/20 自愈、传输期 5/5 旧固件照常起）、
> **掉卡缓存容量实测外推 7.0 小时**、**修掉一个让整机静默的死循环**（`SD_Init` 里 8 位循环变量装不下 300）。
> 同一天还改了按键（PB1 回显开关 / PA0 短按翻页·长按关机）、加了串口三层静默与 OLED 三页显示。
>
> 早期文件（10-18~10-21）有介质层异常：**368,290 行二进制垃圾**（含 PNG 块头），
> 10-29 的 tick 台阶仍未定案，详见 §5 与 `docs/limitations.md`。
>
> 阶段 1~4 全部完成（采集链 / SD 落盘 / RTC + 记录级 CRC + 看门狗 / Bootloader 串口升级），
> 阶段 5（PC 上位机）有一半：格式化、对时、升级、SD 日志分析（含曲线）、串口数据页。
>
> 本文件所有数字都标注来源与状态：**✅ 实测 / 🔶 核算 / ⬜ 计划**。计划中的不会写成已完成。

## 0. 2026-11-09 这一版改了什么

| 模块 | 接口 | 引脚 | 备注 |
|---|---|---|---|
| MCU | STM32F103CBT6 | — | 72 MHz / 20 KB RAM / **128 KB Flash**（Bootloader 16 KB，App 108 KB，参数区 4 KB）|
| 调试串口 | USART1 | **PA9(TX) / PA10(RX)** | 115200-8-N-1；RX 用于对时、升级、命令 |
| OLED 0.96" | 软件 I2C | **PB10(SCL) / PB7(SDA)** | 2026-10-20 从 PB8/PB9 换过来（原插座 VCC/GND 打反，见 `OLED.c` 头注释）|
| MPU6050 | 软件 I2C | PA2(SCL) / PA3(SDA) | 三轴加速度 + 角速度 + 片内温度 |
| BMP280 | 软件 I2C（与 MPU6050 共用）| PA2 / PA3 | 气压 ×10 Pa；地址 0x76/0x77 |
| DS18B20 | 单总线 | PB14 | 需 4.7 kΩ 上拉 |
| **DHT22** | 单总线（开漏）| PB15 | 模块自带 10 kΩ 上拉 |

| SD 卡模块 | 硬件 SPI1 + 软件 CS | PA4(CS) / PA5(SCK) / PA6(MISO) / PA7(MOSI) | 模块必须供 5 V；卡 ≤32 GB 且 FAT32 |
| ADC | ADC1 + DMA（循环）| PA1(光照) / PB0(电池分压 1/3) | 后台自动刷新 `AD_Value[]` |
| 蜂鸣器 | GPIO 输出 | PB12 | 低电平触发 |
| 电源键 | GPIO 输入 | PA0 | 短按 = 翻页（数据/存储/运行）；长按 = 安全关机握手 |

引脚规划的教训：

- I2C 原本想放 PB6/PB7，被 OLED 模块物理遮挡，杜邦线插不进去
- 选引脚要三查：复用/JTAG 表 + 板上实物 + 已用引脚表
- PC14/PC15 是 LSE 晶振脚，动它们等于让 RTC 停摆（见 `OLED.c` 换脚注释）

## 2. 软件架构

```
task_ACQ (6) ──Record_t 44B──▶ [队列 深度 8] ──▶ task_PROC (2)
 100ms 硬节拍                                       │ 出队 → 拼 CSV 行
 绝不阻塞                                           │ 填 512B 乒乓缓冲（传指针，零拷贝）
                                                    ▼
                                          [缓冲指针队列] ──▶ task_SD (1) ──▶ FatFs ──▶ SD
task_KEY (2)    20ms  ──▶ 暂停/STAT/长按关机
task_DISP (1)  200ms  ──▶ OLED（唯一所有者）+ 超时黑屏
task_sensor (1) 1s    ──▶ DS18B20 + BMP280 + DHT22 + 超声波
task_GOLDEN (1) 一次性 ──▶ 把当前固件备份进 W25Q64（金副本）
```

| 任务 | 优先级 | 栈（字）| 周期 | 职责与约束 |
|---|---:|---:|---|---|
| ACQ | 6 | 128 | 100 ms | 采样并组装记录；`xQueueSend` 超时 0，绝不阻塞；漏拍会记账 |
| PROC | 2 | 320 | 队列驱动 | 拼 CSV、填乒乓缓冲；唯一的高频串口打印者 |
| KEY | 2 | 64 | 20 ms | 三态状态机消抖；禁止 printf（栈不够）|
| DISP | 1 | 224 | 200 ms | OLED 唯一所有者；心跳 + SD 错误码；30 s 无操作黑屏 |
| sensor | 1 | 320 | 1 s | 单总线温度 + 气压 + 湿度 + 超声波 |
| SD | 1 | 448 | 队列驱动 | **全工程唯一允许调用 `f_xxx` 的地方** |
| GOLDEN | 1 | 192 | 一次性 | 后台把内部 Flash 拷进 W25Q64 |

三条设计铁律：

1. **SD 的慢被压在低优先级后台**，ACQ→PROC 采集链按设计不等待 SD（实测生产路径 11k：`f_write` avg 10.07 ms、max 124.5 ms；0% 干净卡 10k p99 10 ms；不是“永不阻塞”，I2C 互斥仍用 `portMAX_DELAY`。一块 512 B 缓冲攒满 500 ms，最坏一笔约占 1/4）
2. **FatFs 只允许出现在 `task_sd.c`**（`_FS_REENTRANT=0`），从架构上消灭并发而不是加锁
3. **所有任务的内存都是静态分配的**（`.bss` 里的具名数组），堆只剩 64 B，`map` 能逐项对账

## 3. 存储与可靠性

### 文件命名

```
YYMMDDNN.CSV    数据文件，NN = 当天第几个（01 起）
YYMMDD90.CSV    事件文件（# 开头，PC 解析器跳过）
```

- **按本地日期切换**（`MyRTC_GetLocalDateTime`），本地 00:00 换新文件
- 一天约 864,000 行 ≈ 80 MB

### CSV 格式（17 列）

```csv
seq,tick,press,rtc,ax,ay,az,gx,gy,gz,temp_ds,temp_chip,humi,light,vbat,sonar_mm,crc
1,100,1021230,1793697276,-213,-1115,1669,1,-1,-1,-32768,2303,65535,2278,2088,52,2675
```

| 列 | 含义 | 无效值标记 |
|---|---|---|
| `rtc` | **真 Unix 秒（UTC）** | 0 = RTC 没走（见 §6）|
| `temp_ds` | DS18B20，×100 ℃ | `-32768` = 转换未完成 |
| `humi` | DHT22，×10 %RH | `65535` = 未读到 |
| `light` / `vbat` | ADC 原始值 0~4095 | — |
| `sonar_mm` | 超声波距离 mm | 0 = 无回波 |
| `crc` | 前 16 列文本的 CRC-16/KERMIT | — |

### 可靠性机制

| 机制 | 做法 |
|---|---|
| 写放大控制 | 512 B 攒块写（SD 最小写单位即扇区）|
| 落盘节奏 | 每批 `f_sync`，承诺「掉电最多丢最近一批」；EXP-03 实测 2~6 行/次（8 次）|
| 缓冲所有权 | 乒乓双缓冲，队列传指针；拿了必须交，否则泄漏停摆 |
| 掉卡缓存 | 卡不在时数据进 W25Q64，**故障期间降采样 1 条/秒**，卡回来自动重放（`# SD_REPLAY`）|
| 写失败处理 | 真 `FR_*` 错误立即卸载卷、每 3 s 重试；只有“短写”才走 3 连击 |
| 安全关机 | 长按电源键 → 停采集 → 写完队列 → `f_close` → 屏显 `SAFE TO OFF` |
| 固件金副本 | 升级前把当前固件存进 W25Q64；Boot 可回退 |
| 丢数据记账 | 6 种丢失原因各一个计数器，冲进事件文件（`# LOST,<rtc>,<n>,<reason>`）|
| 可观测性 | 队列满、丢条、SD 错误码、栈水位、堆水位，全部可查。**丢东西可以，不能静默地丢** |

## 4. 时间（RTC）

三条规则，写在 `MyRTC.h` 里：

1. **CSV 的 `rtc` 列永远是 UTC**，不带时区。换时区/跨时区拷数据都不会歧义
2. **给人看的时间（文件名、屏显）加 8 小时**，走 `MyRTC_GetLocalDateTime()`
3. **「配过」和「对过」是两件事**：`BKP_DR1` 说有初始化过，`BKP_DR5` 说有人对过时

本板**已装 CR2032**，正常断电后 RTC 继续走（开机看到 `BKP magic hit -> keep counter` 就是证据）。
只有换电池、备份域被复位、或 LSE 起不来这几种情况，才会退回"用编译时刻当初值"。
已在跑但时间不对时，用串口 `T<unix>` 或 `time_sync.py` 对时。

python 杂项文件\PC工具\sd_analyze.py E:\ --md 报告.md     # 导出 Markdown

界面上也有：`recorder_gui.pyw` → **SD 卡分析** 页（选盘 → 开始分析 → 看明细 / **曲线…** / 导出）。
分析在后台线程跑，不用连串口。

**曲线窗口**的版式照主界面"实时数据"页那组曲线来（同一种"标题 + 最新值 + 量程"的格子），
共六格 + 一条分布：

| 图 | 看什么 |
|---|---|
| 温度 / 气压 / 湿度 / 电池 / 光照（各一格）| 逐小时均值，自动定标；右上角是"最新值 ｜ 最小~最大" |
| 每小时行数 | 柱子塌下去 = 那段时间没采集；红虚线是 10 Hz 满值 36000 行/时 |
| 采样节拍分布 | tick 步长六档柱状（对数刻度），带条数和百分比 |

**三个交互**（2026-11-08 加）：

- **鼠标悬停**：竖十字线贯穿六格，每格在自己曲线上打点，气泡显示那一小时的全部读数；
- **左键拖动**：框选一段放大，标题栏显示当前范围（`[11-07 15 ~ 11-08 10，20/43 小时]`）；
- **右键 / 双击**：复位到全览。放大后每格的量程会重算，说明"局部看"和"全局看"的极值不一样。

> 示例图：`杂项文件\PC工具\SD分析-曲线示例.png`、`SD分析-交互示例.png`（悬停）、`SD分析-缩放示例.png`（框选后）。
> 都是 2026-11-08 用卡上 148 万行数据出的。

**查两份东西**：一份是"这数据可不可信"，一份是"这数据说了什么"。

| 类 | 项 | 判据 / 输出 | 对应固件机制 |
|---|---|---|---|
| 完整性 | 行级 CRC | 逐行重算 CRC-16/KERMIT，统计坏行 | 记录行最后一个逗号前的文本 |
| | seq 缺口 | 按见过的最大 seq 算缺多少条 | 队列满 / 写卡失败 / 掉电在途批 |
| | 回写插入 | seq 变小但 rtc 变大 ⇒ 掉卡缓存把旧记录追加在后面 | `Sd_DsPush` + 回写 |
| | 板子重启 | tick 归零且 seq 继续变大 | IWDG / 手动复位 |
| 数据内容 | 采样节拍 | tick 步长分档（=100ms / 101~150 / … / >2s）、最大一步、累计停采 | 设计值 10 Hz |
| | 通道统计 | 每通道 最小/最大/均值/标准差/p1·p99/有效%/越界/最长同值（已换算物理单位） | 各传感器 |
| | 逐小时均值 | 温度、气压、湿度、电池、光照，看漂移 | 时间戳用 rtc |
| | 通道异常 | 全程一个值 / 全无效值 / 超声连续不动 | 传感器没接、I2C 掉线 |
| | 事件文件 | `YYMMDD90.CSV` 里的 `# LOST` / `# SD_REPLAY` / `# SD_RECOVER` | 掉卡事件 |

> 两个缺口口径要一起看：**seq 缺口**是"产生了但没落盘"，**tick 缺口**是"根本没产生记录"。
> 两者差很多的时候工具会直接说一句，别只报一个数。

**自检锚点**：`python sd_analyze.py --selftest` → `crc16("123456789") == 0x2189`。
锚点不过就别看结论（CRC 参数错了整张报表都是假的）。

## 6. 串口升级（不需要 ST-Link）

PC 侧：`杂项文件\PC工具\flash_app.py`（或双击 `升级固件.bat`；也可以开 `recorder_gui.pyw` 点"固件升级向导…"）

```text
python flash_app.py              # 完整升级：探针 → 请求复位 → 传 → 校验 → 跳转
python flash_app.py --check      # 只算体积和 CRC，不连串口
python flash_app.py --stage data # 只发数据不发 X（验证写 Flash 那一段）
```

> ⚠️ 升级模式里**空闲 30 秒会自己退回 App**（`UP_IDLE_CANCEL_WAITS`）。
> 所以两条线之间别停太久；真被取消了就再发一次 `U`。

协议（文本行，`\r\n` 结尾）：

```text
PC → MCU : E<字节数>        D<块号><hex>        X<整体CRC16>        U（请求进 Boot）
MCU → PC : E0/E1   K<块号>   N<块号>   PASS   FAIL <原因>   WAIT
```

**停等**：每块 128 字节，等 `K` 才发下一块。原因是擦写 Flash 时关中断，串口那段时间的字节会丢。

**先落盘再切换（2026-11-07，U3）**：整包先写 W25Q64 暂存区（`0x7E1000`，108 KB），
每页写完立刻回读比对；`X` 校验通过后才动内部 Flash。
所以**传输期间断电不影响旧固件**；搬运到一半断电，下次开机会自己把暂存区那份装回去
（串口打 `G: stage ok -> installing`）。

**升级前 App 会把当前固件存进 W25Q64 金副本，Boot 只读它回退**，所以升坏了能回退。
自愈有两条兜底：暂存区装不回来 → 金副本恢复 → 再不行才停在升级模式等人。

## 9. 已知不足与 roadmap

| 项 | 状态 |
|---|---|
| Tickless idle（`configUSE_TICKLESS_IDLE`）| ⬜ 未启用：HAL/内核时基冲突，且实测大头是屏幕与 LDO，收益小 |
| STOP 模式 | 💡 候选：要真做电池供电才考虑 |
| SD 卡满后的处理 | ✅ 已实现：<200 MB 告警，<80 MB 删最旧（至少保留最近 3 天；每次挂载最多删 3 个）|
| P-MOS 断电重挂 SD（掉卡终极解法）| ⬜ 未实现：PB10 被 OLED 占用后计划挪到 PA15 |
| 金副本单槽掉电安全 | ⚠️ 未做：保存窗口不是掉电安全；下一版双槽/提交头 |
| PVD 掉电检测 | ⬜ 未做：目前只有每批 `f_sync` + IWDG + 安全关机握手 |
| Modbus RTU 从机 / 上位机 GUI 增强 | 💡 候选 |

完整边界（单卡、8 次掉电、缓存容量未测、10-29 未定案等）见
[docs/limitations.md](docs/limitations.md)；主张/证据对照见
[docs/evidence-matrix.md](docs/evidence-matrix.md)。
