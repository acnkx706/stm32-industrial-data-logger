# 离线分析工具：卡拔下来之后怎么看

从 README 挪出来的。这部分是 PC 工具的使用说明，不是固件本身的事，写太长会盖住主 README。

工具都放在本机 `杂项文件\PC工具\`，没有进这个仓库（那些脚本里带本机路径，而且改得比较随意）。

## 判什么

它回答两个问题：「这批数据可不可信」和「这批数据说了什么」，不是只数行数。

| 类 | 项 | 判据 / 输出 | 对应的固件机制 |
|---|---|---|---|
| 完整性 | 行级 CRC | 逐行重算 CRC-16/KERMIT，统计坏行 | 记录行最后一个逗号前的文本 |
| | seq 缺口 | 按见过的最大 seq 算缺多少条 | 队列满 / 写卡失败 / 掉电在途批 |
| | 回写插入 | seq 变小但 rtc 变大，说明掉卡缓存把旧记录追加在后面 | `Sd_DsPush` + 回写 |
| | 板子重启 | tick 归零而 seq 继续变大 | IWDG / 手动复位 |
| 内容 | 采样节拍 | tick 步长分档（=100 ms / 101~150 / … / >2 s）、最大一步、累计停采 | 设计值 10 Hz |
| | 通道统计 | 每通道 最小/最大/均值/标准差/p1·p99/有效%/越界/最长同值（已换算物理单位）| 各传感器 |
| | 逐小时均值 | 温度、气压、湿度、电池、光照，看漂移 | 时间戳用 rtc |
| | 通道异常 | 全程一个值 / 全无效值 / 超声连续不动 | 传感器没接、I2C 掉线 |
| | 事件文件 | `YYMMDD90.CSV` 里的 `# LOST` / `# SD_REPLAY` / `# SD_RECOVER` | 掉卡事件 |

两个缺口口径要一起看：**seq 缺口**是"产生了但没落盘"，**tick 缺口**是"根本没产生记录"。
两者差很多的时候工具会直接提示一句，别只看一个数。

## 怎么跑

```powershell
python 杂项文件\PC工具\sd_analyze.py E:\                 # 扫整张卡
python 杂项文件\PC工具\sd_analyze.py E:\ --md 报告.md     # 导出 Markdown
python 杂项文件\PC工具\sd_analyze.py --drives             # 先找哪个盘是卡
python 杂项文件\PC工具\sd_analyze.py --selftest           # 自检锚点
```

界面上也有：`recorder_gui.pyw` → **SD 卡分析** 页，选盘 → 开始分析 → 看明细 / 曲线… / 导出。
分析跑在后台线程，不用连串口。

自检锚点是 `crc16("123456789") == 0x2189`。锚点不过就别看结论，CRC 参数错了整张报表都是假的。

## 曲线窗口

版式照主界面"实时数据"页那组来（同一种"标题 + 最新值 + 量程"的格子），六格加一条分布：

| 图 | 看什么 |
|---|---|
| 温度 / 气压 / 湿度 / 电池 / 光照（各一格）| 逐小时均值，自动定标；右上角是"最新值 ｜ 最小~最大" |
| 每小时行数 | 柱子塌下去就是那段时间没采；红虚线是 10 Hz 满值 36,000 行/时 |
| 采样节拍分布 | tick 步长六档柱状（对数刻度），带条数和百分比 |

三个交互：

- **鼠标悬停**：竖十字线贯穿六格，每格在自己曲线上打点，气泡显示那一小时的全部读数
- **左键拖动**：框选一段放大，标题栏显示当前范围（`[11-07 15 ~ 11-08 10，20/43 小时]`）
- **右键 / 双击**：复位到全览。放大后每格量程会重算，所以"局部看"和"全局看"的极值不一样

示例图：`杂项文件\PC工具\SD分析-曲线示例.png`、`SD分析-交互示例.png`（悬停）、
`SD分析-缩放示例.png`（框选后）。都是 2026-11-08 拿卡上 148 万行数据出的。

现在用 `is_record_file()` 先判一下文件名和后缀；16 列的旧格式文件也单独处理。
