## 1. 现状（先读这三段，少走两小时弯路）

- 板子：`STM32F103C8T6`，Boot 16 KB @`0x08000000`，App 108 KB @`0x08004000`，参数区 4 KB @`0x0801F000`
- 固件：FreeRTOS V11.1.0（全静态分配）+ FatFs R0.12c + W25Q64 做金副本与掉卡缓存
- 数据路径：`task_ACQ`(10 Hz) → 队列 8 → `task_PROC`(拼 CSV、攒 512 B) → `task_SD`(f_write + 每批 f_sync) → SD 卡

- 升级：串口 `E/D/X` 自定义协议，先落盘 W25 暂存区再切换，支持防回滚与自愈

**已经做过什么**：17 天账本、拔卡/坏卡/掉电、SD 延迟分布、时间基（tick vs RTC）、升级断电 25 次。全部有原始数据落在 `evidence/`。

## 3. 五类复查任务

### 3.1 数字复核（优先级最高）

从 `evidence-matrix.md` 的 25 条里**随机抽 8 条**，每条做三件事：

1. 它引用的原始文件是否存在、路径对不对；
2. 那个数字在原始文件里能不能找到**一模一样**的值；
3. 它写的"边界/不能说的话"是否真的把这个数字的适用范围框住了。

**常见失分点**：数字对、但样本量或条件被悄悄放大了（比如"单卡平静状态"被写成"实测过"）。

### 3.2 代码与注释一致性

代码注释里写了大量实测数字与日期。抽查 `task_sd.c` / `golden.c` / `freertos_demo.c` 各 5 处，看：

- 注释里的数字和代码里的常量是否一致；
- 注释描述的流程是否还成立（有没有被后来的改动绕过）。

**已知这类问题出现过多次**（例：注释写"一批 40 条"实际 5 条；注释写 112 KB 实际 108 KB），所以**很可能还有**。

### 3.3 逻辑与边界

重点看四个地方（这里最容易藏真 bug）：

| 位置 | 看什么 |
|---|---|
| `task_SD` 的三态机（挂载/未挂载/关机） | 状态切换有没有遗漏路径？关机时最后一批会不会丢？ |
| `Sd_DsPush` / `Sd_DsFlush` 的攒批 | 缓冲区边界、`s_ds_len`/`s_ds_lines`/`s_ds_t0` 三者是否始终一致 |
| `golden.c` 的环形缓存 | `wr/rd` 回绕、擦扇区前的检查、掉电时指针原子性 |
| `Boot/main.c` 的六条判据 | 变量是"快照"还是"实时读"？有没有死赋值？ |

### 3.4 "说了但没做/没测"的话

扫一遍 `README.md`（根目录）、`release/README.md`、`docs/架构总览.md`，找：

- 用了"实测""验证过""保证"这类词，但 `limitations.md` 里又写着没做的；
- 把"设计目标"写成"已实现"的。

### 3.5 最近改动的回归风险

2026-11-10 一天内改了 5 处（都已提交在 `717e595`）：

| 改动 | 风险点 |
|---|---|

## 6. 判定标准（什么算发现）

✅ 算：能指出某句话与某个文件/某段代码/某个原始数字矛盾，且矛盾会影响结论。
✅ 算：能指出某条路径在特定条件下会出错，并给出触发条件。
❌ 不算：没有证据的"我觉得这里可能有问题"。
