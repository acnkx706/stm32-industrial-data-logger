# 储液罐液位项目 · 超声温度补偿分析

> 日期：2026-11-16
> 结论：温度补偿在 1 米以上液位是**必需**的（±20mm/10°C），但**现有数据无法验证**，需要专门采集一次实验。

---

## 一、固件现状：换算常数是写死的

`Hardware/HC_SR04.c`：

```c
*mm = (uint16_t)(((uint32_t)s_us * 172u) / 1000u);   /* 0.172 mm/us */
```

这个常数对应 **声速 344 m/s**，反推温度 = (344 − 331.3) / 0.606 ≈ **21°C**。

也就是说：**固件是"按 21 度的房间标定"的**。房间一冷一热，读数就系统性地偏。

---

## 二、理论推导

声速与温度的关系（20°C 附近常用近似）：

```
c(T) = 331.3 + 0.606·T     [m/s]
```

固件按常数 `c₀ = 344 m/s` 换算，所以读数与真实值的关系是：

```
读数 = 真实距离 × (344 / c(T))
误差 = 真实距离 × (344/c(T) − 1)
```

**误差是"相对值"，所以液位越高，绝对误差越大。**

## 四、为什么"温补"在储罐场景是必需的

储罐液位的典型精度要求是 **±10 mm**（否则液位计量没意义）。

对照上表：

- 1 米液位、房间从 15°C 升到 30°C ⇒ 误差从 +11mm 变到 −16mm，**跨度 27mm**
- 4 米液位、0°C 到 40°C ⇒ 误差跨度 **283mm**

**这个量级完全盖过储罐的精度要求。** 所以温补不是优化，是前提。

而且包里有 DS18B20 —— 温度本来就在测，补偿几乎零成本：

```c
/* 距离(mm) = 脉宽(us) × (331.3 + 0.606·T) / 2000 */
mm = (uint16_t)(((uint32_t)s_us * (3313u + 6u * T_celsius)) / 20000u);
```

（`3313 = 331.3×10`、`6 = 0.606×10`；`us=23300, T=20` 时结果 4000mm，全程 uint32 不溢出）

## 五、现有数据为什么验证不了

尝试用 2026-10 的 26 天数据做验证，**失败**。

### 尝试一：全量线性拟合

取唯一 sonar 有大段有效读数的 `26102901.CSV`（31.7 万有效样本，温度跨度 5.13°C）：

```
实测斜率：+3.526 mm/°C
理论预测：−0.167 mm/°C   （该段距离只有约 95mm）
```

差 20 倍、方向还相反。

**原因**：那天目标不固定 —— 读数在 88 / 105 / 115 / 136 mm 之间跳，是不同物体或移动的物体。

### 尝试二：只取"目标稳定"的段

筛选条件：连续 ≥600 拍、sonar 标准差 <3mm、距离 >300mm、温度跨度 >1°C。

**结果：零个符合条件的段。**

### 根本原因：信噪比不够（这是关键）

温度引起的读数变化率：

```
d(读数)/dT ≈ −真实距离 × 0.606 / 344 ≈ −真实距离 × 0.001762   [mm/°C]
```

| 距离 | 每 °C 变化 | 5°C 跨度总变化 | 超声波噪声 | **信噪比** |
|---|---|---|---|---|
| **100 mm（现有数据）** | 0.18 mm | 0.9 mm | ±2 mm | **0.4** ❌ 测不出 |
| 500 mm | 0.88 mm | 4.4 mm | ±2 mm | 2.2 ⚠️ 勉强 |
| **1000 mm** | 1.76 mm | 8.8 mm | ±2 mm | **4.4** ✅ 可测 |
| 2000 mm | 3.52 mm | 17.6 mm | ±2 mm | 8.8 ✅ 明显 |

**现有数据的 sonar 都在 100mm 附近 —— 那个距离上温补效应比噪声还小，物理上不可能测出来。**

## 六、要验证需要什么实验

| 条件 | 要求 | 理由 |
|---|---|---|
| 目标距离 | **≥1000 mm** | 信噪比需 >3 |
| 目标性质 | 平整硬面（墙/木板/静水面） | 保证回波稳定 |
| 目标位置 | **全程固定不动** | 否则看到的是目标移动，不是温漂 |
| 温度跨度 | **≥10 °C** | 变化要能盖过噪声 |
| 采集时长 | ≥2 小时 | 让温度自然变化 |
| 记录 | 每 10 秒存一条（或直接用 10Hz 原始数据） | — |

**最省事的做法**：把探头对着墙固定好，量出真实距离（卷尺），放一整天（早晚温差通常有 5~10°C），第二天取数。

## 七、对项目的意义

这份分析本身就是"实战性"的证据，因为它做了三件事：

1. **把"温补"从"我觉得该做"变成"算出来必须有"**（1 米 ±20mm，超过精度要求）
2. **给出了补偿公式和定点实现**（不改架构，一行代码）
3. **诚实说明现有数据验证不了，以及为什么** —— 信噪比 0.4，物理上不可能

**第 3 点尤其重要**：说"我算出来了但我验证不了，因为需要 1000mm 距离和 10°C 温差，而我现有数据只有 100mm 和 5°C" —— 这比硬凑一个"验证通过"可信得多。

## 九、可复用工具与实跑结果（2026-11-16 补）

### 工具

`evidence/level_tcomp/sonar_tcomp.py`

```
python sonar_tcomp.py --file <CSV>     # 在真实数据上统计补偿量
python sonar_tcomp.py --demo           # 只出理论表和场景外推
```

核心函数只有三行：

```python
C_FIRMWARE = 0.172 * 2000.0        # 344.0 m/s，固件常数反推
def c_of_t(T):      return 331.3 + 0.606 * T
def compensate(mm, T): return mm * c_of_t(T) / C_FIRMWARE
```

### 实跑：`26102901.CSV`（30 万行）

| 项 | 值 |
|---|---|
| sonar 有效样本 | 291,894（97.3%） |
| 温度范围 | 22.93 ~ 28.56 °C（跨度 5.63） |
| 读数范围 | 78 ~ 402 mm（中位 88 mm） |
| 补偿量中位 | +0.75 mm |
| 补偿量范围 | **1.84 mm** |
| 读数标准差 | 补偿前 19.77 → 补偿后 20.07 |

**结论：补偿量跨度 1.84 mm，小于超声波 ±2 mm 噪声 ⇒ 这份数据看不出效果，与第五节的信噪比分析一致。**

补偿后标准差反而略增 0.3 mm，原因：这批读数本身在 78/88/105/115/136 几个值之间跳（目标不固定），补偿只是整体平移了 0.3~2 mm，并不能减小那种跳变。
