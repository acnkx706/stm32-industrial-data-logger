# 这张卡的文件系统健康状态（2026-11-06 11:56 只读检查）

> 触发原因：删掉 `FILLER.BIN` 之后发现"文件长度合计"和"卷已用"差了 599 MB，
> 于是跑了一次**只读**的 `chkdsk E:`（没有 `/F`），把卡的真实状态查清楚。
> 结论：**卡的文件系统确实有毛病，但今天所有实验数据完好**。

---

## 一、chkdsk 报了什么

命令：`chkdsk E:`（只读，不加 `/F`，退出码 3 = 发现问题但不修）
原始输出：`chkdsk_readonly.txt`

| 问题 | 原文 | 涉及对象 |
|---|---|---|
| 根目录里有**重名条目** | `More than one 26101801.CSV entry in folder \.` | `26101801.CSV` ×2（一个 22,995,040 B，一个 0 B） |
| 时间戳非法 | `\???  Invalid time stamp.` | `70010101.CSV` / `70010190.CSV`（日期显示 1601-01-01） |
| 起始簇非法 | `\???  first allocation unit is not valid. The entry will be truncated.` | 一个文件名已经坏掉的条目 |
| 长文件名条目失效 | `Removing nonvalid long folder entry from \...` | 若干 |
| **丢失簇** | `597557248 bytes in 845 recoverable files.` | 845 条不属于任何文件的簇链，共 **597.5 MB** |

空间账（chkdsk 自己给的）：

```
3,956,801,536 bytes total disk space
       32,768 bytes in 1 hidden files
1,466,499,072 bytes in 45 files
1,892,646,912 bytes available on disk
```

45 个文件 1.466 GB + 丢失簇 0.598 GB + 可用 1.893 GB ≈ 3.956 GB，账是平的。

## 二、这次检查有没有改动卡

**没有。** 三个证据：

1. 命令没带 `/F`，chkdsk 自己打印
   `Windows found errors on the disk, but will not fix them`。
2. 检查前后各列一次根目录，都是 43 个文件 + `System Volume Information`，
   逐项名字、大小、时间戳完全一致（重名的 `26101801.CSV` 那两条也还在）。
3. 检查完之后把 24 个有 SHA256 记录的文件全部重算了一遍：
   **24/24 与 `../longrun/out/manifest_17d.csv` 一致，0 个不符、0 个缺失。**

## 三、这些毛病是什么时候来的

能确定的：

- 重名条目和 1601 时间戳都是 **10-18 / 10-21 那批文件**的事，早于 10-22 的干净窗口。
  所以 EXP-01 用 10-22 ~ 11-01 那 11 个文件做的结论**不受影响**。
- 丢失簇有 845 条、597.5 MB，规模远大于一次拔卡能造成的量，
  更像是 10:29 那次 PC 侧 1.5 GB 写入被中途打断（写缓存没落完就拔卡）留下的残骸。

不能确定的：

- 没法判断这些丢失簇是今天造成的还是更早就在。
- 没法判断卡控制器本身是否健康（那是另一类实验：坏卡/拔卡属于 EXP-03）。

## 四、为什么没有跑 `chkdsk /F`

`/F` 会做两件事，两件都不想要：

1. 把 845 条丢失簇**转成 845 个 `FILE0000.CHK` 文件**堆在根目录里，
   等于凭空往证据卡上加 845 个垃圾文件。
2. 删掉重名的 `26101801.CSV` 条目之一，等于改动证据目录本身。

所以只做只读检查、把结论记下来；真要修，等把 1.36 GB 数据另存之后重新格式化这张卡。

## 五、对后续实验的影响

- **不影响任何已采集的时间数据**（延迟、丢条、CRC 都是板上跑出来的，与 FAT 无关）。
- **影响"卡还剩多少空间"的记账**：卡上永远有 597.5 MB 被丢失簇占着，
  所以这张卡的"可用空间"比标称少 15%。后续任何填充率实验都要按 chkdsk 的口径算，
  不能按"文件长度合计"算。
- 卡上还留着 `EXP02.BIN`（65 MB，全速模式的写入文件），是测试残渣。
  留着不占多少地方，删掉也不会影响任何报告——报告引用的是串口日志，不是这个文件。
