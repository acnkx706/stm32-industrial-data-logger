# 0% 干净基线：格式化后的卡跑 10k 全速

> 固件：`Objects/app_fast10k.bin`（70,288 B，Code=66288；样本数 10,000）
> 原始日志：`clean0_10k.log`（11,405 B，本地保留）

## 一、结果

| 项目 | `f_write` | `f_sync` |
|---|---:|---:|
| 样本 n | 10,000 | 10,000 |
| 平均 | **3.48 ms** | **3.60 ms** |
| p50 | 2 ms | 3 ms |
| p90 | 5 ms | 5 ms |
| p99 | 10 ms | 13 ms |
| max | **27.98 ms** | **89.48 ms** |
| ≥100 ms | 0 | 0 |
| ≥256 ms | 0 | 0 |
| 桶和 | 10,000（满） | 10,000（满） |

**这一轮的分位数是可信的**：n=10,000 < 65,535，`uint16` 桶没有饱和，桶和正好 10,000。
之前 100k 那几轮 `p90=p99=256` 是饱和导致的假数，不能引。

`free_KB` 这一轮也第一次是对的：板子报 `3,863,936 KB`，实际可用 3,956,670,464 B，
换算下来一致。原因很简单——**这张卡是 Windows 格式化后干净卸载的，FSInfo 没有过期**。
所以 `f_getfree()` 不是永远错，它错在"PC 侧写过东西但没刷盘"这个特定情形（已复现两次）。

## 二、填充率三个点放在一起

全部是**全速模式、同一块 512 B 写 + 一次 `f_sync`、追加同一个文件**，只有卡的状态不同：

| 占用 | 卡的状态 | n | `f_write` 平均 | `f_write` max | `f_sync` 平均 | `f_sync` max |
|---|---|---:|---:|---:|---:|---:|
| **0%** | 格式化后干净卡 | 10,000 | **3.48 ms** | **27.98 ms** | 3.60 ms | 89.48 ms |
| 52% | 脏卡（845 丢失簇） | 10,000 | 3.65 ms | 28.49 ms | 3.80 ms | 42.98 ms |
| 91.5% | 脏卡 + `fsutil` 占位 | 100,000 | 3.63 ms | 72.07 ms | 3.77 ms | 48.93 ms |
| 91.5% | 脏卡 + 真写 1.48 GB | 100,000 | 3.64 ms | 67.19 ms | 3.80 ms | 51.16 ms |
| 91.5% | 脏卡，静置 47 分钟 | 100,000 | 数据丢失 | — | 3.77 ms | 48.00 ms |
| 36% | 脏卡，**生产路径**（抢占多） | 11,000 | 10.07 ms | 124.46 ms | 11.38 ms | 126.12 ms |

**怎么读这张表：**

1. **同一套代码（全速模式）下，占用率从 0% 涨到 91.5%，平均只慢约 4%**（3.48 → 3.63~3.64）。
   不是"越满越慢一个数量级"。
2. **同样 1 万次的两个点几乎重合**：0% 的 max 是 27.98 ms、52% 是 28.49 ms，差 2%。
   所以"0% 与 52% 没有区别"这句话是站得住的。
3. **唯一例外是 91.5% 那次 10k 的 942.34 ms**，而它在 20 万次复跑里再没出现。
   按 1/10⁴ 的发生率算，20 万次零出现的概率是 e⁻²⁰ ≈ 2×10⁻⁹
   ⇒ **不是稳态性质**（推导见 `结论-两臂对比.md`）。
4. **生产路径那一行不能和上面五行比**：它的计时窗口里包含任务抢占和队列等待，
   平均 10.07 ms 里有约 6 ms 是等 CPU，不是等卡。混在一起说会把结论带偏。

## 三、能说什么、不能说什么

**能说**：

- 这张格式化后的干净卡，0% 占用下 1 万次写：平均 3.48 ms、p99 10 ms、max 27.98 ms。
- 占用率 0% → 91.5% 对平均写延迟的影响约 4%，对常见分位数几乎没有影响。
- 卡在介质层面健康（全容量写满 + 拔插 + 读回 0 个坏块，见 `卡健康基线-20261106.md`）。

**不能说**：

- 不能说"填充率对尾部没有影响"。0% 和 52% 是 1 万次的样本，尾部本来就看不清；
  91.5% 有 20 万次样本，max 也只有 72 ms —— 但 72 ms 比 28 ms 大，
  这个差别是真的还是抽样造成的，1 万 vs 10 万的样本量差异无法排除。
  真要回答，得在 0% 和 52% 上也各跑 10 万次（约 13 分钟一个点）。
- 不能说"脏卡和干净卡一样"。0% 那轮是干净卡，52%/91.5% 那几轮是脏卡，
  两个变量（占用率、卡状态）同时变了，这一轮设计分不开它们。
- 不能引 89.48 ms 这个 `f_sync` max 当"0% 反而更差"的证据：它只有一次，且在 3.8 万秒刻度上，
  属于单次事件，不能和 91.5% 的 48 ms 比大小。
