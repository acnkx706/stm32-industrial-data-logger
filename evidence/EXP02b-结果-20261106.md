## 0. 一句话

**942 ms 没复现。** 在两个重建的"91.5% 占用"条件下各跑 10 万次写，
一次 ≥256 ms 都没有（最坏 72.07 ms）；卡在介质层面健康（全容量写满 + 拔插 + 读回 0 坏块）；
占用率 0% → 91.5% 只让平均写延迟变慢约 4%。

## 2. 结果

### 2.1 942 ms 复现（两臂）

| 臂 | 填卡方式 | 占用 | n | `f_write` 平均 | `f_write` max | `f_sync` max | ≥100 ms | ≥256 ms |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| A-占位 | `fsutil` 瞬时分配 1.558 GB | 91.57% | 100,000 | 3.63 ms | 72.07 ms | 48.93 ms | 0 | **0** |
| A-真写 | 真实写 1.48 GB（163.7 s，9.3 MB/s） | 91.50% | 100,000 | 3.64 ms | 67.19 ms | 51.16 ms | 0 | **0** |

**统计论证**：原事件是 10k 里出 1 次（≈1/10⁴）。若真是这个发生率，
20 万次零出现的概率是 `(1−1e-4)^200000 ≈ e^−20 ≈ 2×10⁻⁹`。
⇒ **942 ms 不是这张卡在 91.5% 占用下的稳态性质**，但**不能写"已解决"**。

### 2.2 卡健康

| 步骤 | 结果 |
|---|---|
| 格式化 | FAT32 / 簇 32,768 B / `LOGGER` / 0.00%（清掉 845 条丢失簇 597.5 MB、重名条目、1601 时间戳） |
| 写满 | 3,773 块 × 1 MiB = 3.956 GB / 424.9 s / **9.3 MB/s** / **零写错** |
| 拔出重插后读回 | 3.956 GB / 86.5 s / **45.7 MB/s** / **mismatch = 0** |

⇒ 介质层没有可检出的坏块；之前那些毛病都在文件系统层。

### 2.3 填充率三个点（全速模式，只有卡状态不同）

| 占用 | 卡状态 | n | `f_write` 平均 | `f_write` max | `f_sync` 平均 |
|---|---|---:|---:|---:|---:|
| **0%** | 干净卡 | 10,000 | **3.48 ms** | **27.98 ms** | 3.60 ms |
| 52% | 脏卡 | 10,000 | 3.65 ms | 28.49 ms | 3.80 ms |
| 91.5% | 脏卡 | 100,000 | 3.63 ms | 72.07 ms | 3.77 ms |
| 91.5% | 脏卡 | 100,000 | 3.64 ms | 67.19 ms | 3.80 ms |
| 36% | 脏卡，**生产路径**（抢占多） | 11,000 | 10.07 ms | 124.46 ms | 11.38 ms |

- 0% → 91.5%，平均只慢约 **4%**。
- 同样 1 万次的两个点（0% 与 52%）max 只差 2%。
- 最后一行不能与上面比：计时窗口里有任务抢占，10.07 ms 中约 6 ms 是等 CPU。

### 2.4 0% 干净基线的分位数（唯一可信的一组）

n=10,000 < 65,535，`uint16` 桶没饱和：

| | `f_write` | `f_sync` |
|---|---:|---:|
| p50 / p90 / p99 | 2 / 5 / **10 ms** | 3 / 5 / **13 ms** |
| max | 27.98 ms | 89.48 ms |

## 3. 三个候选解释，一个都没被证明

1. **卡内 GC 块合并**：最自然，但真写 1.48 GB 后延迟一点没变差，这条被削弱。
2. **未刷卷的残留状态**：原事件那次卡是**直接拔的、没 `Write-VolumeCache`**，
   板子 mount 到"FSInfo 说 1.88 GB、实际 385 MB"的文件系统。这个现象今天又复现两次
   （`free_KB=1,825,184` / `1,775,200`，实际 336 MB），但"卡侧还有没落完的活"这个状态没能重建。
3. **计时窗口被抢占**：`DWT->CYCCNT` 量墙上时间，全速下 `task_SD` 与 `task_DISP` 同为优先级 1、
   时间片轮转。支持证据：全程 66 万次窗口里，唯一大量出现 ≥100 ms 的是生产路径那轮（225 次），
   全速两臂 20 万次里 0 次。反证：这两臂 DISP 照样在跑，却没出 942 ms。

**报告里按"未定案"写，不许挑一个顺眼的当结论。**

## 4. 顺带改掉的两个旧说法

1. **`free_KB` 不可信 → 收窄为"PC 侧写过但没刷盘时才不可信"。**
   格式化后干净卸载的卡上，`free_KB=3,863,936` 与实际完全一致。
2. **`void 直方图饱和` 的范围要说清：n > 65,535 就丢样本**。
   100k 那几轮桶和只有 8 万，`p90=p99=256` 是假数；10k 那几轮桶和是满的，分位数可信。

## 5. 能说 / 不能说

**能说**

- 91.5% 占用下 20 万次写：平均 3.63~3.64 ms、max 67~72 ms、≥100 ms 为 0 次。
- 占位与真写两种填卡方式对延迟无可测影响。
- 卡在整容量范围内可读写，无坏块。
- 0% 到 91.5% 平均延迟差约 4%。

**不能说**

- "942 ms 已解决"——只能说"20 万次未复现"。
- "卡完全健康"——只做了一遍写+读，没做多轮/温度/寿命。
- "填充率对尾部没有影响"——0% 和 52% 各只有 1 万次，尾部看不清；
  而且这两点是干净卡与脏卡混着的，卡状态和占用率两个变量没拆开。
- 任何 100k 轮次的分位数。
