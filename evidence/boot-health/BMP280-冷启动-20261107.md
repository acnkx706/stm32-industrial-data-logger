# BMP280 冷启动固定读 692.3 hPa —— 定位、修复与验证

> 日期：2026-11-07
> 板卡：STM32F103CBT6 + FreeRTOS，App ver 74（App 区 108 KB，参数区 4 KB）
> 涉及提交：`559a353`（BMP280 时序）、`cd4c73e`（SD 重试预算）、`fd7cd1f` / `7216342`（release 重出）
> 原始日志：`stm32/exp/serial-u1u2.log`（每行带 PC 时间戳）；统计脚本 `stm32/exp/boot_health.py`

---

## 1. 一句话

冷启动（断电足够久）后气压恒读 `692.3 hPa`、温度恒读 `23.29 C`，**每次一个数不差**；
热插拔/软复位完全正常。根因是 `BMP280_Read()` 在写 `CTRL=forced` 之后**立刻**读 `measuring` 位，
把"还没开始转换"当成"已经转换完成"，于是读到的永远是**上一次**的结果；冷启动时没有上一次，
寄存器还是复位值 `0x80000`。

---

## 2. 现象

开机自检那三行（`BMP280_BootTest()`）：

```
BMP280 init = 0 (0=OK / 1=ID wrong / 2=no bus)
BMP280 selftest: T=2508 (expect 2508)  P=100653 (expect 100653)
BMP280 selftest: PASS
BMP280 raw : press=692390 (x10Pa)  temp=2329 (x100C)
BMP280 real: press=692.3 hPa   temp=23.29 C
```

三个反常点：

1. 当地大气压约 **1028 hPa**，692.3 差了 336 hPa，物理上不可能；
2. **14 次开机，两个数完全一样**（692390 / 2329），不是噪声；
3. 同一次开机里，运行时的记录 `press<1029xxx>` 是**正常**的。

---

## 3. 关键观察：冷启动 vs 热插拔

| 情况 | 结果 |
|---|---|
| 拔插间隔很短（~1 秒，电容没放完） | `press=1029.x` 正常 |
| 断电 2 秒以上、真的复位 | `press=692.3`，每次都一样 |
| ST-Link 烧录后复位（不断电） | `press=1028.5` 正常 |

这个差异是定位的钥匙：**热插拔时传感器没有真正掉电**，它内部还留着上一次的转换结果，
所以"读上一次"这件事看不出来；冷启动时寄存器回到复位值，才暴露。

## 5. 排除法：为什么不是接线或供电

最初的假设是"杜邦线/电源接触不良"，被三条证据否掉：

1. **数值固定**：接触不良的读数会跳、会随机，不会 12 次停在同一个数上；
2. **只有一个器件坏**：同一次开机里 OLED、SD、DS18B20、DHT22 都正常，
   若真是 3.3V 轨塌陷，它们不会全好；
3. **系统没复位**：那段时间 SD 卡里记录一直在写（`seq` 连续递增），
   说明 MCU 既没掉电也没被看门狗咬，只是"读回来的值不对"。

结论：**不是电气问题，是软件读到了错误的状态**。

---

## 6. 根因

`Hardware/BMP280.c` 的 `BMP280_Read()`（修复前）：

```c
if (BMP_WriteReg(BMP_REG_CTRL, BMP_CTRL_FORCED) != 0u) { return 1u; }

for (t = 0u; t < 100u; t++)
{
    if ((BMP_ReadReg(BMP_REG_STATUS) & 0x08u) == 0u) { break; }
    DWT_Delay_us(500);
}
```

- BMP280 的 `status` 寄存器 bit3 `measuring` 表示"转换进行中"；
- 写完 `CTRL` 之后，这个位要**过几毫秒**才会置 1；
- 代码紧接着读，读到 0，判据 `== 0` 成立 → 立即 `break`；
- 于是读到的是**上一次**留在数据寄存器里的结果。

冷启动时没有"上一次"，`0xF7~0xFC` 还是复位值 `0x80000`
（手册写明：本次测量被跳过时为 `0x80000`），代入补偿公式得到固定的 692.3 hPa / 23.29 C。

运行时之所以看起来正常：上一次是 1 秒前的真实值，数值合理，**只是慢了 0.5~1 秒**，
没有任何人会发现。

---

## 7. 修复

```c
	/* 写完 CTRL 后先等它真正开始转换 */
	DWT_Delay_us(5000);

	for (t = 0u; t < 100u; t++)
	{
		if ((BMP_ReadReg(BMP_REG_STATUS) & 0x08u) == 0u) { break; }
		DWT_Delay_us(500);
	}
	if (t >= 100u) { return 2u; }
```

```c
	/* 0x80000 = 本次测量被跳过，读到它说明没测成，不能拿去换算 */
	if ((adc_P == 0x80000) || (adc_T == 0x80000)) { return 4u; }
```

第二段是"护栏"：即使时序再出问题，也不会把无效值当成数据吐出去。

## 8. 验证与代价

- 冷启动 2 次：`1027.0 hPa` / `1027.0 hPa`，不再出现 692.3；
- `i2c_max` 1516 → 1511 µs，`drop=0`、`qmax=1`，ACQ 采样无丢包 —— 5 ms 延迟没有伤实时性；
- 代码 +24 字节（`Code 65,784 → 65,812`）。

## 9. 影响面（必须说清楚）

- **数据**：修复前，每次冷启动最多有 **1 条**记录可能是 `press≈692300`（第一拍读到复位值），
  之后自动恢复。要清查历史数据，按 `,692xxx,` 搜 CSV；
- **时效**：修复前所有气压值都比实际晚 0.5~1 秒，时间戳对不上；
- **掩盖性**：热复位、快速拔插都看不出来，只有"真正断电足够久"才暴露
  ——这类 bug 在实验室按"重启一下试试"的方式测试是测不出来的。

---

## 10. 边界（不能说的）

- 只测了**一块板、一颗 BMP280**，没有第二颗器件交叉验证；
- 692.3 这个具体数字与校准系数有关，**换器件数值会变**，不能当成通用常量；
- 没有示波器测 I2C 波形，"measuring 位延迟"是从手册时序和现象推的，没有直接观测；
- 冷启动一共只验了 2 次（后续 T5 补做），样本量小。

---

## 11. 附带发现：SD 卡初始化次数分布很宽

同一批日志里，`SD: ACMD41 ready after N tries` 的 N 从 **5 到 156** 都有：

| 观测 | N | 说明 |
|---|---:|---|
| 多数开机 | 5~7 | 卡已带电/刚用过 |
| 长时间断电后 | 152~156 | 约 1.5 秒，接近规范上限 |

而原来的 `SD_INIT_TIMEOUT_MS` 是 2000 ms，对 156 次只剩 25% 余量；
11:08 那次 `E:03`（`CMD0 NO RESPONSE after 200 tries`，连续 3 轮）
就是卡没醒够、预算先用完。

已把预算放宽到 **3000 ms / CMD0 300 次**（`cd4c73e`），代价是最坏情况开机多等 1 秒。
**这两组数字只对这张卡成立，换卡必须重测。**

## 13. T5：16 次冷启动验收（2026-11-07 13:15~13:20）

U1/U2 计划里的 T5 是"10 次随机断电"，实际做了 16 次，全部通过：

| 检查项 | 结果 |
|---|---|
| 气压 | 16/16 在 **1026.5~1026.9 hPa**，有 0.4 hPa 自然波动 |
| OLED | 16/16 `OLED: found 1` |
| SD | 16/16 `SD_Init=0`、`ACMD41` 6 次、`f_mount OK` |
| 参数区 | 16/16 `PARAM: img=1 boot=0 seq=21 flags=00`（正常启动一次没写） |
| gold | 16/16 `GOLD: W25 ok, backup crc=67A5` |

**为什么这组数据比"12 次 692.3"更有说服力**：修复前是**同一个数**（读的是常量），
修复后是**一个小区间**（1 次/秒的真实读数），"有波动"本身就是"真在读传感器"的证据。

### 13.1 这轮没测到什么

- 16 次的 `ACMD41` 全是 6 次 —— 因为插拔间隔只有 ~20 秒，卡一直半带电，
  **慢速初始化那条路径这轮没被覆盖**。慢速路径的证据只有 13:03 / 13:08 两次（152/155 次）。
- 没有测"断电时间很长（几分钟以上）"的情况。
- 陀螺仪那段 16 次全部不合格，原因是人在反复插拔、板子在动；
  校准要求静止 2 秒，**这不是故障**，别记成异常。

### 13.2 能说与不能说

- 能说：修复后连续 16 次冷启动，气压、OLED、SD、参数区全部正常；
- 不能说：**"断电不会砖"**。16 次只是 16 次，给不出概率；
  而且这 16 次全部是"正常插拔"，没有做"传输中途拔电"。
